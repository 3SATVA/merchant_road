# Architecture

Static site, no build step. `index.html` is a thin shell (markup + help text) that loads one stylesheet and 46 classic `<script>` files in a fixed order. It works over `file://`, any static server, Vercel and Capacitor.

## Why classic scripts (not ES modules)
- Every top-level `const`/`let`/`function` in one classic script is visible to the scripts after it. The code moved over verbatim, with no import/export wiring across about 1,500 statements and no renames.
- ES modules don't load over `file://` (CORS), and they would need hundreds of explicit imports. A missed one only shows up at runtime.
- What to watch for: a function declaration hoists only inside its own file. Anything that **runs while loading** (building terrain, sprites, icons, the boot call) may only use files loaded before it, or its own file. The regression harness fails on any load-time `ReferenceError`.

## Load order (index.html)
`core/touchguard` (head), then:
core/util, core/registry, world1/data, world2/data, inventory/data, core/world, core/wings, world2/art, core/player, core/horse, assets/icons, assets/sprites, assets/ui-icons, assets/portrait, core/state, core/economy, core/cart, core/input, core/canvas, core/ui, core/town, core/hud, inventory/inventory, inventory/forge, inventory/enchant, inventory/enchanter, core/play, core/render, core/scenery, core/worldswitch, world1/enemies, world1/caves, world1/witch, world1/wagon, world1/scrap, world1/weather, world2/islands, world2/sky, world2/skyfoes, world2/wingcart, world2/weather, world2/cutscene, world2/dock, world2/airships, world2/skyisles, world2/trees, world2/capital, world2/autumnfoes, core/loop (boots the game), core/testhooks.

The data files load first because terrain, town biomes and sprite sheets are built at load. Gameplay files only run when called, so their position among themselves doesn't matter. Keep `core/loop.js` near the end.

## Registries and save safety
`ITEMS`, `TOWNS`, `BIOMES`, `BIOMEINFO` and `SPAWNS` are arrays, and **their indices are save data** (cargo item/origin, `lastTown`, `visited`, biome of a town). They are append-only: `reg(list, expectedIndex, [...])` throws if anything is registered out of order. Current layout:
- ITEMS: World 1 goods 0–5, World 2 goods 6–9, Aldenreach goods 10–12 (Spiced Amber, Emberleaf Tea, Hearth Cider)
- TOWNS: World 1 0–5, World 2 6–8 (8 = Aldenreach)
- BIOMES, BIOMEINFO, SPAWNS: World 1 0–4, World 2 5–9 (8 = autumn wilds, 9 = the capital)

`ENEMY`, `HAULERS`, `COFF` and `HITCHR` are keyed objects (World 1 keys first, then World 2).
Save format, field names and the `merchantRoad.v1` key are unchanged. New fields are only ever added (and created lazily), e.g. `S.sky={r:{island:S.time taken},st:storm toast seen}` from the sky islands; a save without it loads as before. Never rename save fields or reorder `load()` migrations.

## Per-world state
- `WORLDDEF[n]` (in `worldN/data.js`) holds everything that used to be an `if(WI)` branch: length, biome bands, X limits, caves, terrain formula `rawH`, extra flat ground, pit builder, decor rule, arrival town/money/position, and the world's **cart** (`cart()`, `leave()`, `carry`, `autoHitch`, `parkIco`). `setWorld(n)` copies it into the current-world globals (`WORLD`, `BOUNDS`, `NB`, `WB`, `XMIN`, `XMAX`, `WT`, `DUNGEONS`).
- `S.park` is the parked cart of the **current** world only. On a world switch, `WORLDDEF[w].leave()` files it into `S.ws[w]` and `enterW` restores the other world's park. `curH()` asks the current world's def which cart it owns: the wagon in World 1, the Winged Cart in World 2.
- Timers: `env` (core/play.js) holds run timers shared by both worlds (biome, spawn distance, autosave, lift). World 1 storms and rocks live in `W1ENV` and only tick in World 1. World 2 weather and leap timers live in `W2ENV`. `travelTo` clears a running World 1 storm, as before.

## Sky islands (world2/skyisles.js)
- `SKYISLES` in `world2/data.js` (`x0,x1,h` surface height, `top` 0 aqua / 1 lilac grass, `storm`, reward `rw` chest/wool/crystal at `rx` from the centre, `foes`). `UNI` holds the unicorn bolt numbers (and `gap` between burst bolts), `SKYI` the reward cooldowns and amounts, `STORMIN` how far inside the island the storm starts.
- They are ordinary World 2 ground: `onIsle(x)` covers `ISLES` plus `skyAt(x)`, `WORLDDEF[1].rawH` gives them their height, and `isleTh` their thickness, so landing, walking, horse summon and `groundAt` need nothing new. `islAt` stays town islands only, so decor, docks, the Winged Cart park and `onIsleX` (save migrations, death respawn) ignore sky islands.
- Foes with `isle:1` (`unicorn`, `dreadUni`, `bigSlime`, `isleSlime` = the big slime's halves) are `air:1` enemies, so `updAir`/`drawAir` route them to `updIsle`/`drawIsleFoe`. `skyTick` (called from `w2Tick`) spawns them when an island comes near and despawns them when it is far, and the flier cull and `spawnAir` count skip them. In flight their hits go through `airHit`/`cartHit` like other sky foes.
- Storms: `stormAt(x,lane)` (see Flight lanes below); `canFly()` is false in a storm lane, so `updSky` drops you onto the island (`stormDrop`, toast once) and you take off again past the cloud's edge or fly a clear lane.
- Drawing hooks: `drawClouds` calls `drawSkyProps` (grass, roots, crystals, rewards), `drawWeather` calls `drawStorms` and `drawBolts`. Plain clouds overlapping an island are skipped (`c.isl`).
- Size and shape (layout v2, `W2L`): the five islands are 600-1060px wide (2.65-2.73x the first layout), spaced 300-700px apart between Skyhaven (x1 1950) and Sunspire (now 8800-10600, dock 8990, town 9750; `W2LEN` 11000). `isleH(I,x)` gives each one gentle rises and dips plus `ld` ledges (`[u0,u1,dh]` as fractions of the width; 14px ramps, i.e. walkable terraces, since the heightfield has no overhangs). The first and last `SKYI.pad` px are kept flat for landing / take-off. `skyTh` hangs a fixed-depth belly under the base height. `isleProps` places crystals, boulders, bushes, flowers, tufts and hanging roots (decor only, cached in `SKYPROP`).
- Foe spacing: `skyTick` splits `x0+SKYI.safe .. x1-SKYI.safe` into one slice per foe with `SKYI.gap` between slices; each foe spawns in its slice centre and patrols only inside it (`e.z0/e.z1`, the big slime's halves inherit it). Rewards sit at the centre (`rx` offset), so they are 270-500px from either end.
- Storm clouds cover the whole island (`x0-14 .. x1+14`); rain and the no-fly core stay `STORMIN` inside.
- Storm cloud placement (`stormBox` in world2/skyisles.js; the look is the pre-lane one: dark `#465068` cloud columns, heavy slanted rain, jagged lightning): the cloud sits in the top storm lane, its top `STORMTOP` (20px) above that lane's top (the lane above is always clear, its rider flies 40px higher), and its base at least `STORMGAP` (40px) above the island's highest point (`I.sTop`, cached). Where the lane is too short the cloud is scaled down (`k`, island 8: 0.75; islands 2 and 4 are full size with ~100px gaps). The dark tint runs from the cloud top down to the island top, never over the island; rain falls from the cloud onto the core. Island 8 sits at h 150 with lower ledges to leave that gap. Rain zones (world2/weather.js) use the pre-lane rain cloud at the top of their top rain lane (`LANET[lh]-10`, base above the rider) with rain down to the bottom of their lowest lane. (The 2b70ba6 lanes commit had commented the rain cloud out by accident: rain zones drew no cloud.)

## World 2 flight lanes (world2/data.js, world2/sky.js)
- Three lanes: `BANDY` [-70,-190,-310] is the cruise height of low / middle / high. Lanes are soft: `laneOf(P.y)` reads the lane from your actual height (midlines `LANEB` -130 / -250); `P.band` is only the lane you are heading for (up / down / `tj`). The high lane keeps the `JET` tailwind.
- Every sky island has a lane `ln` and a surface height `h` just under that lane's cruise height (low ~55-62, middle ~172-178, high ~292-298). `skyTh` bellies are at most ~68px, so the rider one lane down passes underneath.
- `flyTarget()` over an island: if you are under it you are held below its belly (no more popping up onto it from underneath). If you are above it in its lane you come down and touch down (`W2ENV.land`, then `horseVanish` as before). In a higher lane you skim over. Towns (`ISLES`) make you land from any lane. `startFly()` takes off into the lane of the island you stand on and sets `P.toff`, so you don't land straight back on it; it clears once you leave that island. Down in the island's lane over it still lands you.
- Island foes only notice you on the island or in its lane (`near` in `updIsle`; autumn foes already need you on the island), so passing over or under skips its fights, chest and resources.
- Storms: `storm:n` covers the island's own lane and the n-1 lanes above it (`stormLn`). It never covers a lane below, so a forced drop always lands on the island and at least one lane stays clear (island 2 low+middle, island 4 middle+high, island 8 middle only). `stormAt(x)` with no lane is the island itself (calling the horse there). The cloud sits in the top storm lane (`laneCY`), rain falls from it to the island, and the screen mood is lighter (x0.35) while you fly a clear lane past it.
- Rain zones (`WX`, `k:'rain'`) have `ln` lanes: flight there is `RAINSLOW` (x0.6) slower, and it no longer pushes you down. The cloud and streaks are drawn only in those lanes. Updrafts still lift you a lane, but never into a storm lane within reach (`stormNear`).
- Camera (`skyCam`, used by core/loop.js while flying the sky horse in World 2): eases vertically toward you (target = 60% your height + 40% your lane's cruise height, lerped at 2.5/s so lane bobbing doesn't jitter). You sit ~42% down the screen, between the HUD and the touch buttons; the view is clamped to at most .30 VH of sky above the high lane and to the cloud sea below the low lane, and always keeps you inside the HUD / button margins (short landscape screens simply follow you). On a phone in portrait it moves about 190 px between the low and high lanes. Everything is drawn from `camX/camY`, so parallax, islands, foes, shots and landing need nothing special; the HUD is screen space. World 1 never flies, so its camera is unchanged.
- Altitude indicator (`drawAlt`, next to the up / down buttons): one cell per lane. Gold is your lane, a gold outline the lane you are heading for, hatched violet a storm lane on screen, blue streaks a rain lane, and a white tick shows your exact height.
- Air foes spawn around your lane (`spawnAir`; pegasi at or above it) at unchanged rates, and sky slimes follow you between lanes (40px/s, no mid-lane cap).
- Saves need nothing: World 2 saves keep x only, so a load puts you on the (moved) island surface, or at the dock if you are off any island, and a mid-air save takes off from there into that island's lane.
- Old saves: `WORLDDEF[1].migrate` (run from `load()` via the generic `WORLDDEF[].migrate/fresh` hooks in core/state.js) remaps World 2 positions saved before layout v2 (`S.w2l` missing) with `w2Remap` (piecewise linear `W2K0 -> W2K1`, so a spot on an island stays on the same relative spot, Sunspire moves +2000), then `w2Land` snaps a mid-air position to the nearest island pad within 400px; anything else falls back to the Skyhaven dock as before. Player, horse and Winged Cart park are remapped; new saves carry `w2l:2` and are never remapped.
- To add an island: append to `SKYISLES` (keep it between town islands, at least ~150px from the WX zone edges looks best). Existing save `S.sky.r` keys are island indices, so append only.

## World 2 sky horse vanishes on landing (world2/sky.js)
- In World 2 the winged horse only exists in the air. When a mounted player touches ground (normal landing or a storm drop), `skyHorseTick()` calls `horseVanish(1)`: the player is set on foot, `S.horse` becomes `{on:false,x:-9999}` (`HGONE`, hidden; the minimap pin is gated on `x>-9000`) and a pixel sparkle burst (`SPARKS`, aqua/gold/white plus-shaped motes that rise, shrink and fade; `sparkBurst`/`sparkTick`/`drawSparks`) plays. One-time toast, flag `S.sky.lv`. The game has no audio system, so there is no sound.
- Summon: in World 2 the horse button (`toggleHorse` -> `skyHorseBtn()`, key R) sparkles the horse in under the player, mounted, and calls `startFly()` straight away (a hop into the low band). Mounted-on-ground never persists, so there is no land/vanish loop. Inside a storm the button only fizzles and shows a hint (walk out past the cloud edge, then call it); storm islands are crossed on foot.
- Dismount: there is no horse dismount in the air any more. In horse flight the big right button climbs a band (`tJ` shows `arU`), and only the airship uses it to leave (at a dock). R/X do nothing in horse flight.
- Winged Cart: it stays hitched logically (capacity and cargo unchanged) but is not drawn while on foot (`core/render.js` adds `&&mounted()`). It sparkles away and back with the horse. The cart button still parks or re-hitches it on foot, with a sparkle.
- Saves: `startGame` computes `air` (`S.air` set while horse-flying, or the saved x is off any island) and calls `w2Start(air)`. A mid-air save loads flying as before. A save made on the ground loads on foot with the horse vanished.
- The old on-land plod (`HLAND`, `horsePlod`, `PLODF`) is dormant: `horsePlod()` never returns true because the horse is never mounted on the ground in World 2. World 1 is unaffected; every change is behind `WI===1`.

## World 2 difficulty (world2/data.js)
- World 2 is tuned for a player arriving with end-game World 1 gear, not a fresh character. Foe base stats in `ENEMY` read like World 1 numbers; `W2T` (`hp` 4.5, `dmg` 4, `coin` 3) multiplies every sky foe's hp, dmg and coins once at load (pegasus, skySlime, unicorn, dreadUni, bigSlime, isleSlime), and `UNI.bolt` too. `SKY.dmg` (.6) scales flier contact hits on top of that. Turn one knob, not every stat. `W2HPN` then halves hp for `pegasus`, `unicorn`, `dreadUni` and `bigSlime` (124 / 158 / 248 / 248); `skySlime` (180) and `isleSlime` (108) keep the tier hp. Health bars read `e.max`, set from `ENEMY[t].hp` at spawn, so they scale with it.
- `ENEMY.uni` marks the unicorn behaviour (telegraph, bolt). `burst` is how many bolts it fires per telegraph (`UNI.gap` s apart, same aim, short re-glow before each). `elite` uses the dark-gold palette. `gem` is the chance of dropping a Sky Crystal on death. `dreadUni` is the elite: 3-bolt burst, more hp, essence .7.
- Every hit stays telegraphed and dodgeable: bolts by band change or jump, pegasus dives by changing band during the dive, big slimes by spacing. Storm islands make you cross on foot, so most of the guaranteed fighting happens there.
- Balance profiles live in `tests/regression/reg.js` (`BALPROF.max`: all W1 weapons, Obsidian Blade Sharp III/Crit II/Berserk II, Magma Lance Sharp III/Bloodthirst II, Stone set with Guarded III+Hardy III / Hardy II+Regen I / Guarded II+Thorns II, 170 max HP, 5 potions; `BALPROF.mid`). `BALRUN(profile, 'c'|'r')` is a careful or careless Skyhaven to Sunspire bot. Its result is stored under `<vp>_bal_*_run` in the digest. Targets: careful max arrives at 25-50% HP after at least 1 potion, careless max dies about half the time across seeds, and mid gear is not meant to make it.

## World 2 storm, economy, crystal, weapons and trees
- Storm look (world2/skyisles.js `stormShade`/`drawStorms`, placement `stormBox`): near a no-fly storm the screen fades to a dark blue-grey and desaturates (lighter while you fly a clear lane past it). Cloud placement, rain and lightning are described under the flight lanes section above. It is visual only; the `stormAt` zone is unchanged.
- Economy: Skyhaven sells Cloud Wool and Sunfruit and has a forge (`t.forge`). Sunfruit sells for 500 and Star Silk for 2000. Aldenreach's goods follow the World 1 town ladder (each town's prize good is about x4 the last: wood 30, coal 100, iron 500, gold 2000; Sunfruit 500, Star Silk 2000): Spiced Amber 8000 (was 1200), Hearth Cider 4500 (was 420), Emberleaf Tea 2500 (was 150), all above Star Silk. Margins are the usual percentage spread, so trading stays profitable at the same rate; only the stakes go up. Sky slimes drop Sunfruit (25%) instead of apples. The storm island's old crystal node became a Cloud Wool node.
- Sky Crystal (`skyglass`) is enemy-only: open-sky pegasi and sky slimes drop it at 15%, and unicorns at `ENEMY[t].gem`. It is a material in `S.mats` (older saves that had it as cargo are migrated by `load()`).
- Crystal armor (inventory/data.js): Sky Crystal Helm, Chestplate and Boots, each +30 max HP, -11% damage taken and +5% speed. Wearing all three makes it +45 HP each (`CRYSET`). Each piece costs 6 Sky Crystal + 10 Magic Essence at the Skyhaven forge. World 2 forge recipes carry `w:1` (`recipesHere` filters on `(r.w||0)===WI`). The shop chips come from `need`.
- Cultist armor (inventory/data.js `GEAR.cultmask/cultrobe/cultboots`, `SETS.cultist`): a glass-cannon set, crafted only at the Aldenreach forge. Recipes can carry `at:'Aldenreach'` (`recipesHere(t)` also filters on `!r.at||t.name===r.at`, and core/town.js passes the town). Each piece costs 5 Magic Essence + 5 Sun Cloth (`MATS.suncloth`) + 20 Star Silk taken from cargo (`CARGOMAT.starsilk`=9, the ITEMS index; `iron` 4 works the same way). Mask: +12% attack, +8% attack speed, -2% damage taken, +15 HP. Robes: +15% / +10% / -3% / +20 HP. Boots: +8% / +7% / -2% / +15 HP. Gear `atk` sums into `dmgMul()` and `aspd` into `aspdMul()` (inventory/enchant.js), which divides the weapon cooldown in `playerAttack` and `lanceStrike`. With all three worn, `maxHP()` returns exactly `CULTHP` (150), and the set bonus Solar Flare (`SOLAR`: every 5th hit, counted in `P.sol` by `solarHit` at the top of `hitEnemy`) bursts for 60 x `dmgMul()` fire damage to foes within `rx`/`ry` (46/40 px) of the player. The struck foe is left to `hitEnemy` to kill, so it is never killed twice. `FLARES` holds the ring effect (`drawFlares` after PARTS in core/render.js, `tickFlares` in the PARTS tick, `fx` .42 s). The inventory shows the set text, and the stats line shows the attack and speed bonuses. Sprites are in core/player.js, icons in assets/icons.js, and ⚡/☀ glyphs in `EMOG` (assets/ui-icons.js).
- Cog Flail (`FLAIL` in inventory/data.js, `flailSwing` in core/play.js): 50 damage, sold at Skyhaven, works on foot and mounted. It auto-aims vertically. The drawn chain is 58px (`range`). The hit lock reaches `FLAIL.reach` (68) px to a foe's box edge, measured from the hand, with `vk` vertical scaling within `vband`. It splashes `splash` px around the drawn landing point, and the drawn gear hits anything within `pad` px for the whole swing.
- Wind Staff (`WEAPONS.windstaff`): it takes the fire staff's ranged path. `multi` (3) balls go out per cast, `spread` (.12 rad) apart, released `stag` (.07 s) after each other. A ball with `p.wait>0` waits at the staff tip and is not drawn. Each ball does 15 damage x `rng` gear, homes gently (`home` .45 in `steerProj`), lives 1.7s, and has no knockback: the wind hit in core/play.js restores the foe's `vx` after `hitEnemy`, so it doesn't shove. Cooldown .65 (same as the fire staff). The witch set's twin shot does not apply. It costs 6 Sky Crystal + 10 essence at the Skyhaven forge. It can be enchanted, and when mounted it follows the same rule as the fire staff (an equipped lance strikes instead). The projectile `kind` is `'wind'`, drawn in core/render.js; the sprite tip and icon are in assets/sprites.js.
- Sky trees (world2/trees.js): decoration only and never solid. There are 3 variants (puff tree, crystal pine, blossom willow) x 3 sizes x 2 palettes (teal, lilac for `top` isles and the Sunspire biome). Each is pre-rendered once to a 32x44 canvas (`treeImg`); autumn-palette trees (`pl` 2, `m:2`) are re-drawn at 2x size (64x88, same 1px detail) and also keep ±50px from the reward and clear of the autumn set pieces (`AUSETX`) and 22px from DECOR. The capital's own garden trees stay 1x, and only on-screen trees are drawn with `drawImage`. Sky islands (`isleTrees`, drawn inside `drawSkyProps` before the props) stay 34px off the ends, ±36px from the reward and off slopes. Home islands (`homeTrees`, drawn from `drawClouds`) avoid towns, docks (`decorOK`) and DECOR. Positions come from `hash`, so they are the same every run. They are drawn before entities, so they sit behind foes and the player. World 1 is untouched.

## World 2 autumn wilds and the capital (world2/capital.js, world2/autumnfoes.js)
- Layout: `W2LEN` is 19600. `ISLES[2]` (16450–19300, `cap:1`) is Aldenreach; `CAPW` holds the wall ends (gatehouses), the tower door x and the two decorative piers. `SKYISLES` 5–9 sit between Sunspire and the capital; their `au` field gives the autumn look (`au:2` dithers from Sunspire lilac into autumn eastwards, same rule as the trees, see `auAt`), `kind` picks a set piece (`castle`, `rubble` with the sun-cult flag, `shrine`, `grove`), and `rw:'leaf'` is an Emberleaf bush (an autumn chest gives Spiced Amber instead of Star Silk). Biome 8 is the open autumn sky (`AIRB=[6,8]` are the biomes with open-sky flyers), biome 9 the capital. The first-arrival cutscene pan stops at `CUTEND` (11000) so it is unchanged.
- The capital is drawn from one cached canvas (`capArt`: curtain wall, wall towers, procedural half-timber houses, trees, stalls, Vex's Tower, gatehouses) plus a few live layers (smoke, flags, lamps, townsfolk, piers). It is culled outside the island. `auDecor` draws the autumn DECOR kinds (`d.b>=8`).
- Vex's Tower: `nearTowerDoor` (World 2 only) puts the prompt up; E/tap enters `DG={tower:1}`, which `renderDungeon`/`updDungeon` hand to `renderTower`/`updTower`. `TOWER` holds the floors, ladders, door and Vex positions. It is one tall shaft with a single ladder (ground floor to Vex's landing): up/W/tU anywhere on the ground floor slides you to the ladder and auto-climbs, down/S/tD anywhere on the landing climbs down; `towerCamY` keeps the ground floor at 62% height (clear of the touch buttons) and eases up to the landing. The cart stays hitched (it is invisible on foot inside) and is back on exit with its cargo; entering clears the toasts so the region banner does not cover the room. tU/tD show while inside (core/hud.js). Talking to Vex sets `WTOWER=1` and opens the enchanter, so enchanting is only possible at the top of the tower. `ENCHT` (inventory/enchant.js) gives the tower price (6 essence, 2x the wagon), curse chance (.057 per roll, 92% curse-free vs 77%) and stronger results: 1/2/3 enchants at 25/45/30% (wagon 60/30/10) and level II/III only at 55/45% (wagon I/II/III 55/33/12).

## Aldenreach shops (world2/capital.js, core/town.js)
- `CAPSHOP` lists four buildings inside the walls (Forge, Stables, Carrier, Smith), each `{x,w,tab,n,c}`. Their spans join `CAPEX`, so the procedural houses leave room (World 2 only). `capShops` paints the facades into the cached `capArt`, and `capShopLive` adds the forge glow and sparks plus a door glow when you're near. `nearCapShop` (on foot, on the ground, World 2) drives the prompt in core/play.js (`capShopPrompt`), and E/tap calls `enterTown(TOWNS[8],tab)`, which opens the town panel on that tab. Aldenreach carries `forge:1`, `stable:1`, `carrier:1`, `weapons:['resinsword']`, so the existing tabs are reused: the forge shows the Skyhaven `w:1` recipes.
- Carriage (`HAULERS.carriage`: cap 75, spd .85, $100,000; `COFF`/`HITCHR` set its hitch). World 2 only, same as the Winged Cart (not in `HORDER`). It flies with your horse, sparkles away on landing, and hitches and parks the same way. `isWC(h)` is true for either cart, and `drawW2Cart` picks the art (`drawCarriage` in world2/art.js). Save: `S.carriage` (owned) and `S.w2c` (`'carriage'|'wingcart'`, which one is in use); both are optional. `WORLDDEF[1].cart()` returns the active one. The haulers tab at a carrier town lists it, and switching is blocked while parked or when the cargo is over the new cap.
- Pegasus ($50,000, `PEGPRICE`, Stables tab). You must own the winged sky horse first. Save: `S.peg` (owned) and `S.mnt` (`'peg'|'horse'`). `pegOn()` is true only in World 2, and then `vmax` in world2/sky.js is x`PEGSPD` (1.5) in flight. World 1 always rides your own horse. `drawHorse(...,peg)` uses the white and gold palette with `PEGWING` (core/wings.js), and `pegURL()` is the lazy icon.
- Resin Sword (`WEAPONS.resinsword`: 50 dmg, reach 24, $50,000 at the Smith). `perm:[{k:'sticky',l:3}]` is a permanent enchant: `encList` always prepends `W.perm` and drops duplicates from `S.ench`, so re-enchanting can't remove it. `ENCH.sticky` has `perm:1` and empty `w`, so it never rolls on other items. The look is an amber tint (alternating with the ice tint when both apply) plus resin drips (`drawEnemyFx`/`resinDrips`). The blade is amber with animated drips (assets/sprites.js). ## How to add…
**An enemy to World 2:** add it to `Object.assign(ENEMY,{...})` in `world2/data.js` (use `base:'slime'|'goblin'|'golem'|'witch'` to reuse a ground foe's AI and art, or `air:1` for a flier). Put it in the biome's row of `reg(SPAWNS,5,...)`. A new flier needs its look in `drawAir` (`world2/skyfoes.js`). Same pattern for World 1 in `world1/data.js` (`world1/enemies.js` for new art/AI).

**An item (trade good):** World 2: append `reg(ITEMS,13,[{id,name,base,col}])` after the existing World 2 goods block, then add its index to a town's `sells`. World 1 goods added now also take the next free index (13+), registered from a file loaded **after** `world2/data.js` (for example a new `world1/data2.js` with its script tag right after `world2/data.js`), because indices 6–9 are already World 2's. Its pixel icon comes from `col`, or add one in `assets/icons.js`. Weapons and gear (carry between worlds) go in `inventory/data.js`.

**A town:** World 2: `reg(TOWNS,9,[{name,x,w:1,sells:[...],weapons:[],haulers:[]}])` in `world2/data.js`. `x` must be on an island (`ISLES`). A town's biome is set in `core/world.js` from its x. A World 1 town follows the same next-index rule as items (8+, file loaded after `world2/data.js`, `w:0`).

**A new world:** add `worldN/data.js` with `WORLDDEF[N]` and its registrations at the next free indices. `travelTo`/`setWorld` currently assume two worlds (`n?1:0`); widen those first.

## Restoring the drivable airships
All the code is in `world2/airships.js`, `world2/dock.js`, `world2/islands.js` (`drawShipD`, `liveDocks`) and `core/town.js` (Airships tab), plus `SHIPS`/`SORDER` in `world2/data.js`. Set `FEATURE_DRIVABLE_AIRSHIPS=true` in `world2/data.js`. Before you ship that, give the airship hold its own save field (e.g. `S.shipPark`), because `detachShip`/`attachShip` still use `S.park`, which World 2 now uses for the Winged Cart (see SHELVED.md).
